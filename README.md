# Калькулятор кормовых объектов

**Текущая версия: 1.2.4**

PWA-приложение для учёта выдачи кормовых объектов (крысы/мыши) в зоопарке.
Работает офлайн после первого открытия (Service Worker кеширует все ресурсы).

## Состав архива

- `index.html` — приложение (разметка + стили + логика)
- `sw.js` — Service Worker (офлайн-кеш)
- `manifest.json` — манифест PWA (иконки, название, цвет темы)
- `README.md` — этот файл

## Установка / обновление на GitHub Pages

1. Залить все файлы в корень репозитория (или в соответствующую папку, если Pages настроены на подпапку), перезаписав старые версии.
2. Обязательно проверить, что `CACHE_NAME` в `sw.js` отличается от значения в предыдущей версии — иначе уже установленные на телефонах экземпляры приложения не увидят обновление и продолжат работать со старым закешированным кодом.
3. Данные пользователей (журнал выдачи, поля "Выдал/Принял", несохранённые черновики) хранятся в `localStorage` браузера на устройстве и не зависят от файлов на сервере — замена файлов их не затрагивает.

## История версий

### 1.2.4
- Добавлена валидация: при сохранении записи в журнал теперь обязательно должна быть выбрана должность в полях "Выдал" и "Принял" (не только ФИО), иначе показывается предупреждение и запись не сохраняется.
- У числовых полей ввода количества добавлены атрибуты `inputmode="numeric"` и `min="0"` — на мобильных устройствах теперь показывается корректная цифровая клавиатура без лишних символов (минус, точка).

### 1.2.3
- Персистентность полей "Выдал"/"Принял" переведена с события `onchange` на `oninput` (для текстовых полей ФИО/отдела) — данные сохраняются на каждое нажатие клавиши, а не только при потере фокуса поля, что защищает от потери введённых данных при внезапном сворачивании приложения.
- Импорт JSON-бэкапа теперь запрашивает подтверждение перед перезаписью текущего журнала, с указанием количества записей в текущей базе и в файле — защита от случайной потери данных.

### 1.2.2
- Исправлен основной баг: введённые, но не сохранённые в журнал количества кормовых объектов пропадали при сворачивании приложения (из-за выгрузки страницы из памяти операционной системой). Теперь количество автоматически сохраняется в черновик (`localStorage`) при каждом изменении и восстанавливается при следующем открытии, пока не будет нажата кнопка "Внести в журнал".
- Service Worker обновлён: добавлены `skipWaiting()` и `clients.claim()`, чтобы новые версии приложения применялись сразу при следующем открытии, без необходимости вручную очищать кеш браузера.

### 1.2.1
- Базовая версия на момент начала работы над улучшениями.

## Известные ограничения (запланировано на будущее)

- Резервное копирование (БЭКАП) выгружает только журнал записей; поля "Выдал/Принял" в бэкап пока не включены — их придётся вводить заново при восстановлении на новом устройстве.
- Импорт полностью заменяет текущий журнал, слияние данных с разных устройств не поддерживается.
- Редактирование уже сохранённых записей журнала не предусмотрено — только удаление.
